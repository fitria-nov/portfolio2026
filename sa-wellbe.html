System Requirement Specification

Well-Be Application: Proactive Monitoring System

Platform inovatif yang dirancang khusus untuk memonitor lansia penderita Alzheimer melalui pemantauan lokasi real-time dan manajemen memori digital, memfasilitasi koordinasi perawatan yang lebih baik.

Role

System Analyst

Timeline

2025

Category

Healthcare & IoT

Platform

iOS & Android

1. Introduction

1.1 Purpose

Aplikasi Well-Be adalah inovasi teknologi yang proaktif dalam memonitor lansia penderita demensia, Alzheimer, dan penurunan daya ingat. Fitur utama mencakup Linimasa untuk menyimpan kenangan sebagai terapi kognitif, serta Pelacak Lokasi melalui GPS Tracking secara real-time.

Dokumen ini mendefinisikan persyaratan sistem secara jelas untuk memfasilitasi koordinasi antara pengembang, pengasuh, keluarga, dan tim Quality Assurance (QA). Sistem harus menjamin kinerja responsif, keamanan data yang ketat, dan antarmuka yang intuitif.

1.2 Scope & Environment

Solusi komprehensif ini didesain untuk mengurangi beban pengasuh dan menjaga keselamatan pasien secara proaktif. Sistem terdiri dari aplikasi mobile dan integrasi perangkat *smartwatch*.

Operating Environment: Mendukung minimal Android 8.0+ dan iOS 12.0+. Membutuhkan koneksi internet aktif untuk sinkronisasi data lokasi dan notifikasi real-time dari *wearable device*.

1.3 Definitions & Acronyms

SRS

Software Requirements Specifications — Dokumen standar pendefinisian fitur dan batasan sistem.

GPS

Global Positioning System — Sistem pelacakan lokasi berbasis satelit yang digunakan smartwatch.

Memories

Catatan digital (foto/video/teks) sebagai media terapi kognitif pasien.

Wearable

Perangkat elektronik yang dipakai di tubuh (mis. Apple Watch) untuk memantau data kesehatan dan lokasi.

2. Overall Description

2.1 User Classes

Aktor yang terlibat dalam interaksi dengan sistem Well-Be.

Pasien

Penerima utama layanan. Memiliki akses untuk menyimpan dan melihat momen/memori. Membutuhkan UI yang sangat sederhana dan ramah lansia.

Pengasuh (Caregiver)

Bertanggung jawab atas pemantauan langsung. Memerlukan notifikasi lokasi real-time, pencatatan rekam medis harian, dan fitur kedaruratan.

Keluarga

Pengawas eksternal. Perlu akses ke lokasi terkini pasien, riwayat peringatan, dan berpartisipasi dalam mengelola linimasa memori.

Administrator

Mengelola keseluruhan sistem, data pengguna, performa server, dan pembuatan laporan kesehatan bulanan yang komprehensif.

2.2 Non-Functional Requirements

Performance

Waktu respons data lokasi < 5 detik. Harus mampu menangani 10.000 pengguna aktif dengan konsumsi RAM aplikasi < 500MB.

Security

Enkripsi AES-256 untuk storage dan transmisi. Otentikasi 2FA untuk admin. Terdapat sistem deteksi anomali akses.

Usability

Desain aksesibel untuk lansia. Teks besar, kontras tinggi, ikon jelas, navigasi sederhana, dan umpan balik visual yang intuitif.

2.3 Design Constraints & Dependencies

  • Regulatory: Wajib mematuhi regulasi privasi data medis HIPAA dan perlindungan data GDPR.
  • Hardware: Sistem harus mengoptimalkan konsumsi baterai smartwatch saat pemantauan GPS aktif secara berkelanjutan.
  • Interoperability: API harus kompatibel untuk berintegrasi dengan sistem Electronic Medical Records (EMR) di rumah sakit.
  • Dependencies: Bergantung pada ketersediaan layanan GPS pihak ketiga (seperti Google Maps API) dan pembaruan OS platform.

3. Use Case Specifications

Spesifikasi teknis interaksi antara aktor pengguna dengan sistem fungsional.

UC-01: Melacak Lokasi Secara Real-time

Critical
Primary Actor
Keluarga, Pengasuh
Summary
Melacak koordinat pasien secara langsung menggunakan GPS dari smartwatch yang terintegrasi.
Basic Flow
  1. Pasien memakai smartwatch yang berstatus terhubung.
  2. Pengasuh membuka halaman pemantauan di aplikasi seluler.
  3. Sistem menarik data koordinat secara berkala.
  4. Peta interaktif menampilkan pin lokasi pasien saat ini.
  5. Jika pasien keluar dari zona aman (Geofence), sistem langsung mengirim push-notification darurat.

UC-02: Mengelola Memori (Linimasa)

Therapy
Primary Actor
Keluarga, Pasien
Summary
Fasilitas unggah dan kelola foto/video momen bahagia sebagai instrumen terapi ingatan pasien.
Basic Flow
  1. Anggota keluarga masuk ke modul 'Memories'.
  2. Memilih fungsi unggah (foto/video/teks).
  3. Menambahkan deskripsi dan tanggal momen tersebut.
  4. Data tersimpan dan disinkronisasi ke perangkat pasien.
  5. Pasien dapat menelusuri memori secara kronologis di aplikasinya.

UC-03: Pencatatan Kesehatan Harian

Essential
Primary Actor
Pengasuh, Admin
Summary
Input data kondisi fisik dan psikologis harian pasien untuk evaluasi jangka panjang.
Basic Flow
  1. Pengasuh membuka modul rekam medis harian.
  2. Mengisi parameter kesehatan (tekanan darah, tingkat aktivitas, suasana hati).
  3. Menyimpan catatan; sistem memberikan timestamp otomatis.
  4. Admin dapat mengekspor data komulatif ini menjadi laporan bulanan.

4. User Stories

Role Story Statement
Admin Sebagai Admin, saya ingin mengekstrak laporan perkembangan bulanan agar dapat mengevaluasi kondisi pasien dan melakukan audit kinerja pengasuh.
Pasien Sebagai Pasien, saya ingin melihat foto-foto memori keluarga dengan mudah agar saya dapat mengingat momen bahagia tanpa merasa kebingungan menggunakan aplikasi.
Pengasuh Sebagai Pengasuh, saya ingin menerima notifikasi instan jika pasien keluar dari zona aman agar dapat melakukan tindakan pencegahan atau evakuasi sesegera mungkin.
Keluarga Sebagai Keluarga, saya ingin melihat rute perjalanan pasien hari ini agar memastikan pasien berada dalam pengawasan yang benar dan aman.
