Introduction

Latar belakang, tujuan, cakupan produk, dan definisi istilah.

🎯

1.1 Purpose

1.1.1 Ringkasan Keseluruhan

Aplikasi Well-Be adalah inovasi teknologi yang proaktif dalam memonitor lansia penderita demensia, Alzheimer, dan penurunan daya ingat. Aplikasi ini memiliki fitur-fitur yang mendukung peningkatan kualitas hidup pasien dan mengurangi beban pengasuh, seperti fitur Linimasa untuk menyimpan momen hangat dan bahagia, serta fitur Pelacak Lokasi melalui GPS Tracking secara real-time.

1.1.2 Tujuan Penulisan Dokumen

Mendefinisikan persyaratan sistem secara jelas dan memberikan panduan terperinci mengenai fitur-fitur aplikasi. Memfasilitasi koordinasi antara pengasuh, keluarga, dan tim QA. Memastikan kepatuhan terhadap regulasi keamanan dan privasi data. Ekspektasi mencakup kinerja responsif, keamanan data ketat, antarmuka intuitif, dan kompatibilitas multi-perangkat.

1.1.3 Audiens yang Dituju

Manajer proyek dan investor yang memerlukan gambaran umum fungsi sistem. Organisasi kesehatan untuk validasi kebutuhan klinis. Pengembang dan insinyur sebagai panduan teknis. Tim Quality Assurance (QA) untuk pengujian menyeluruh. Personel regulasi untuk kepatuhan privasi data. Pengasuh dan penyedia layanan kesehatan sebagai pengguna akhir.

🔭

1.2 Scope

1.2.1 System Description

Solusi inovatif untuk memantau dan mendukung pasien Alzheimer melalui fitur-fitur yang memudahkan pengasuh dan keluarga. Fitur utama mencakup pelacakan lokasi secara real-time menggunakan GPS, manajemen catatan kondisi kesehatan pasien, serta memori yang dapat diakses oleh pengasuh dan keluarga.

1.2.2 Product Scope

Solusi komprehensif untuk mendukung perawatan pasien Alzheimer melalui fitur pelacakan lokasi real-time, manajemen catatan kesehatan, dan integrasi dengan perangkat smartwatch. Bertujuan meningkatkan efisiensi perawatan, menjaga keselamatan pasien, dan mengurangi beban pengasuh secara signifikan.

1.2.3 Operating Environment

Platform mobile mendukung Android 8.0+ dan iOS 12.0+. Membutuhkan koneksi internet untuk GPS, notifikasi real-time, dan sinkronisasi smartwatch. Lingkungan operasional: smartphone, tablet, dan cloud storage yang aman.

1.2.4 General Constraint

Peningkatan Kualitas Hidup Pasien: Diukur melalui pengumpulan data rutin (aktivitas fisik, pola tidur, perilaku, suasana hati, fungsi kognitif).

Peningkatan Koordinasi Perawatan: Memfasilitasi komunikasi yang lebih baik antara pengasuh, keluarga, dan tenaga medis melalui notifikasi real-time dan integrasi wearable.

📖

Overall Description

Use Case, kebutuhan non-fungsional, kelas pengguna, batasan desain, dan asumsi sistem.

🔍

2.1 Product Perspective

Aplikasi Well-Be merupakan sistem baru yang berdiri sendiri (self-contained), tidak merupakan pengganti atau pengembangan dari sistem yang sudah ada. Sistem ini terdiri dari komponen mobile application (Android & iOS), backend server dengan REST API, database cloud, dan integrasi perangkat smartwatch melalui Bluetooth/Wi-Fi. Keseluruhan arsitektur dirancang untuk mendukung komunikasi real-time antara pasien, pengasuh, keluarga, dan administrator.

⚙️

2.2 Use Case Specification

UC-01: Melacak Lokasi dengan GPS

Critical
Aktor Utama
Keluarga, Pengasuh, Smartwatch
Summary
Melacak lokasi pasien secara real-time dengan GPS lewat Smartwatch yang sudah diintegrasikan ke sistem Well-Be.
Precondition
Pasien menggunakan smartwatch yang terhubung ke sistem. Keluarga/pengasuh memiliki akses ke aplikasi Well-Be.
Post-Condition
Keluarga/pengasuh mendapatkan informasi terkini lokasi pasien secara real-time di peta.
Basic Path
1. Pasien memakai smartwatch yang sudah dipasangkan.
2. Keluarga/pengasuh masuk ke sistem Well-Be.
3. Sistem otomatis memantau lokasi pasien via GPS smartwatch.
4. Keluarga/pengasuh melihat lokasi terkini di aplikasi pada peta interaktif.
5. Notifikasi dikirim jika pasien berada di area berbahaya atau di luar zona aman.
Exception Path
Jika sinyal GPS lemah/hilang, sistem menampilkan notifikasi peringatan. Jika smartwatch terputus, sistem memberitahu pengasuh untuk memverifikasi.

UC-02: Mengintegrasikan Smartwatch

Critical
Aktor Utama
Keluarga, Smartwatch
Summary
Menghubungkan dan memasangkan smartwatch pasien ke sistem Well-Be untuk pemantauan berkelanjutan.
Precondition
Smartwatch mendukung konektivitas (Bluetooth/Wi-Fi). Aplikasi Well-Be sudah terinstal di smartphone.
Post-Condition
Smartwatch berhasil terintegrasi dan mulai mengirim data lokasi serta kesehatan ke sistem.
Basic Path
1. Admin/keluarga membuka pengaturan perangkat di aplikasi.
2. Sistem mendeteksi smartwatch yang tersedia.
3. Pengguna memilih perangkat untuk dipasangkan.
4. Sistem memverifikasi dan mengkonfirmasi koneksi.
5. Smartwatch terintegrasi dan mulai mengirim data.

UC-03: Mengelola Memories (Linimasa)

Critical
Aktor Utama
Pasien, Keluarga, Pengasuh
Summary
Menambah, mengedit, atau menghapus kenangan/memories yang disimpan dalam aplikasi sebagai media terapi kognitif.
Precondition
Pengguna sudah login ke aplikasi. Koneksi internet tersedia untuk sinkronisasi data.
Post-Condition
Memories berhasil disimpan/diperbarui dan dapat diakses oleh semua aktor yang berwenang.
Basic Path
1. Aktor memilih menu memories/linimasa.
2. Aktor memilih tindakan: tambah, edit, atau hapus.
3. Aktor mengunggah foto/video/catatan terkait momen pasien.
4. Sistem menyimpan perubahan ke cloud storage.
5. Semua aktor terkait mendapat notifikasi pembaruan.

UC-04: Notes Kondisi Kesehatan

Critical
Aktor Utama
Admin, Pengasuh, Keluarga
Summary
Mencatat dan memperbarui informasi terkait kondisi kesehatan pasien secara berkala untuk evaluasi perkembangan.
Precondition
Pengguna memiliki akses ke modul catatan kesehatan. Data pasien sudah terdaftar dalam sistem.
Post-Condition
Catatan kesehatan tersimpan dan dapat diakses untuk pembuatan laporan bulanan.
Basic Path
1. Pengasuh membuka modul catatan kesehatan.
2. Pengasuh menginput data kondisi terkini (aktivitas, suasana hati, gejala).
3. Sistem menyimpan catatan dengan timestamp otomatis.
4. Admin dapat meng-generate laporan perkembangan bulanan.

2.3 Non-Functional Requirements

✅

Functional Suitability

Mencakup semua fitur esensial (GPS, integrasi wearable). Hasil akurat dan relevan untuk pemantauan pasien Alzheimer. Fitur harus sesuai dengan kebutuhan klinis yang telah diidentifikasi.

⚡

Performance

Waktu respons data lokasi < 5 detik (jaringan 4G). Menangani 10.000 pengguna aktif bersamaan. Efisiensi RAM < 500MB di perangkat mobile.

📱

Compatibility

Android (min 8.0 Oreo), iOS (min 12.0). Kompatibel dengan smartwatch: Apple Watch dan WearOS. Mendukung berbagai ukuran layar.

👆

Usability

User-friendly untuk pengasuh dan lansia yang kurang familiar dengan teknologi. Aksesibilitas: teks besar, ikon jelas, navigasi sederhana, dan feedback visual yang intuitif.

🔒

Security

Enkripsi AES-256 untuk storage dan transmisi data. Two-Factor Authentication (2FA) untuk akses data sensitif. Deteksi anomali untuk mencegah akses pihak tak berwenang.

🛡️

Reliability & Portability

Uptime 99.9%. Backup otomatis setiap 12 jam. Cloud sync untuk migrasi antar perangkat dengan mudah. Tetap optimal di jaringan 3G.

👥

2.5 Design & Implementation Constraints

📜

Regulatory Policies

Wajib mematuhi GDPR (General Data Protection Regulation) dan HIPAA (Health Insurance Portability and Accountability Act) untuk menjamin privasi dan keamanan data kesehatan pasien secara menyeluruh.

🔋

Hardware Limitations

Optimalisasi konsumsi baterai pada integrasi GPS smartwatch. Aplikasi harus berjalan lancar di berbagai kelas smartphone, termasuk perangkat entry-level dengan RAM terbatas.

🔗

Interfaces to Other Applications

Harus dapat berintegrasi dengan sistem Electronic Medical Records (EMR) secara real-time untuk pertukaran data kesehatan pasien yang akurat dan terpercaya.

🔐

Security Considerations

Memiliki mekanisme deteksi anomali untuk mencegah akses data dari pihak tak berwenang. Semua transmisi data melalui protokol terenkripsi (HTTPS/TLS 1.3).

📡

Reliability Requirements

Implementasi Handshake Protocols (XON/XOFF atau ACK-NACK) untuk mencegah kehilangan data transmisi GPS. Failover mechanism untuk memastikan layanan tetap berjalan saat terjadi gangguan server.

💡

2.6 Assumptions & Dependencies

📌 Asumsi (Assumptions)

  • Pengguna memiliki koneksi internet yang stabil untuk mengakses fitur real-time.
  • Perangkat smartwatch tersedia dan kompatibel dengan sistem yang dikembangkan.
  • Pengguna memiliki literasi digital dasar untuk mengoperasikan aplikasi mobile.
  • Tersedianya tenaga perawat/pengasuh di area layanan untuk pendampingan pasien.
  • Pihak keluarga bersedia untuk berpartisipasi aktif dalam pemantauan kondisi pasien.

🔗 Dependencies (Ketergantungan)

  • Layanan GPS pihak ketiga (Google Maps API / Apple Maps) untuk pemetaan lokasi yang akurat.
  • Pembaruan OS (Android/iOS) yang rutin untuk menjaga kompatibilitas dan keamanan.
  • Regulasi kesehatan pemerintah yang dapat berubah dan mempengaruhi fitur aplikasi.
  • Keandalan uptime server cloud hosting (AWS/GCP) untuk menjamin ketersediaan layanan 24/7.
  • SDK smartwatch dari vendor (Apple WatchKit, WearOS API) untuk integrasi perangkat.

User Interface & Requirements

Deskripsi role, user story, dan skenario pengguna secara lengkap.

🎭

2.7.1 Deskripsi Role Pengguna

Pasien — Penerima Utama Layanan

Penerima utama layanan kesehatan dalam sistem. Memiliki akses ke sistem untuk menyimpan momen/memori berupa foto, catatan, dan video sebagai media terapi kognitif. Kondisinya dipantau secara real-time (lokasi via GPS smartwatch) untuk memastikan keamanan di manapun berada. Antarmuka dirancang sangat sederhana agar dapat digunakan oleh lansia dengan keterbatasan kognitif.

Pengasuh — Pemantau Langsung

Individu yang bertanggung jawab atas pemantauan fisik dan mental pasien secara langsung dan berkala. Dapat mencatat perkembangan kondisi kesehatan, memberikan notifikasi ke admin dan keluarga jika terjadi perubahan signifikan atau keadaan darurat. Membutuhkan akses cepat ke data lokasi, riwayat kesehatan, dan fitur komunikasi instan.

Keluarga — Pengawas Eksternal

Pengawas eksternal yang peduli terhadap kondisi pasien. Memiliki akses untuk memantau lokasi pasien secara real-time, melihat dan mengelola linimasa memori, serta menerima notifikasi terkait kondisi kesehatan dan peringatan zona bahaya. Berperan sebagai penghubung antara pasien dan pengasuh dalam pengambilan keputusan perawatan.

Admin — Pengelola Sistem

Mengelola keseluruhan sistem termasuk manajemen data pengguna, monitoring performa aplikasi, penjadwalan pengasuh, dan pembuatan laporan. Memiliki akses penuh ke semua modul dan dashboard komprehensif. Bertanggung jawab atas integritas data dan keamanan sistem secara keseluruhan.

💬

2.7.3 User Scenario

Fitur Skenario Pengguna
📍 Melacak Lokasi Secara Real-time 1. Pengguna (pengasuh/keluarga) login ke aplikasi Well-Be.
2. Pengguna membuka halaman pemantauan pasien.
3. Pengguna melihat titik lokasi pasien yang disinkronisasi dari smartwatch.
4. Lokasi selalu terbarui secara real-time pada peta interaktif.
5. Sistem mengirim peringatan jika pasien keluar dari zona aman yang ditentukan.
📸 Mengelola Linimasa (Memories) 1. Pengguna login dan membuka halaman linimasa memori.
2. Pengguna dapat meng-upload foto, video, atau catatan sebagai memories pasien.
3. Pengguna/pasien bisa menelusuri memori tersebut berdasarkan tanggal atau kategori.
4. Sistem menampilkan memori dalam format kronologis yang intuitif.
📋 Mengakses Catatan Kesehatan 1. Pengguna membuka halaman catatan kesehatan pasien.
2. Sistem menampilkan rekam medis, catatan kondisi terkini, dan riwayat perkembangan.
3. Pengguna bisa memfilter dan mencari catatan berdasarkan tanggal, waktu, dan kategori.
4. Admin dapat meng-generate laporan perkembangan untuk evaluasi berkala.
